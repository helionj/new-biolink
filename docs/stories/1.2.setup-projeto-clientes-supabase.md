5. Tipos TypeScript gerados via `supabase gen types typescript` checados em CI; script `pnpm db:types` configurado em `package.json` apontando para o projeto Supabase remoto de dev (não para stack local); output em `lib/supabase/types.ts`. `pnpm db:types` roda sem erro e o arquivo gerado é válido (tsc passa após geração).
6. Migration inicial `supabase/migrations/0001_init.sql` vazia (apenas comentário-placeholder) commitada para reservar a posição da migration; schema real virá em Story 1.4.
7. Documentação em `docs/dev-setup.md` explica como conectar ao Supabase de dev sem rodar `supabase start` — passo-a-passo: criar projeto no dashboard, copiar URL/anon/service-role, popular `.env.local`, instalar Supabase CLI, gerar HASH_SALT, executar `pnpm db:types`, executar `pnpm dev`.

### Client Setup — Código canônico

[Source: docs/architecture.md §Frontend Services Layer > API Client Setup, linhas 1198-1240]

```typescript
// lib/supabase/server.ts — Server Components / Server Actions / Route Handlers
import { cookies } from 'next/headers';
import { createServerClient } from '@supabase/ssr';
import { env } from '@/lib/env';

export async function createClient() {
  const cookieStore = await cookies();
  return createServerClient(env.NEXT_PUBLIC_SUPABASE_URL, env.NEXT_PUBLIC_SUPABASE_ANON_KEY, {
    cookies: {
      getAll: () => cookieStore.getAll(),
      setAll: (toSet) =>
        toSet.forEach(({ name, value, options }) => cookieStore.set(name, value, options)),
    },
  });
}

// lib/supabase/client.ts — Client Components (rare; prefer Server Actions)
import { createBrowserClient } from '@supabase/ssr';
import { env } from '@/lib/env';

export function createClient() {
  return createBrowserClient(env.NEXT_PUBLIC_SUPABASE_URL, env.NEXT_PUBLIC_SUPABASE_ANON_KEY);
}

// lib/supabase/admin.ts — service-role; APENAS em Server Actions/Route Handlers
import { createClient as createAdminClient } from '@supabase/supabase-js';
import { env } from '@/lib/env';

export function createAdmin() {
  if (typeof window !== 'undefined') {
    throw new Error('admin client cannot be used in the browser');
  }
  return createAdminClient(env.NEXT_PUBLIC_SUPABASE_URL, env.SUPABASE_SERVICE_ROLE_KEY, {
    auth: { autoRefreshToken: false, persistSession: false },
  });
}
```

**Implementação literal** — não inventar variações, manter assinaturas/imports como acima.

### Env Vars — Validação Zod

[Source: docs/architecture.md §Tech Stack + §Architectural Patterns linha 146]

Schema esperado em `lib/env.ts`:

```typescript
import { z } from 'zod';

const EnvSchema = z.object({
  NEXT_PUBLIC_SUPABASE_URL: z.string().url(),
  NEXT_PUBLIC_SUPABASE_ANON_KEY: z.string().min(1),
  SUPABASE_SERVICE_ROLE_KEY: z.string().min(1),
  HASH_SALT: z
    .string()
    .min(32, 'HASH_SALT must be at least 32 hex chars; generate with `openssl rand -hex 32`'),
});

export const env = EnvSchema.parse(process.env);
```

> **Importante:** `parse` (não `safeParse`) — queremos build failure imediato com mensagem clara. Validação ocorre na primeira importação do módulo (Next.js carrega no boot).
