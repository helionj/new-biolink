## Story

**As a** desenvolvedor,
**I want** uma tabela `page_views` (append-only, PII hashada) + um endpoint `POST /api/track/view` (com dedup window de 30min por `ip_hash+page_id`, hash sha-256 + salt para `ip`/`user-agent`, e rate-limit reusado do 4.1) + um Client Beacon mínimo embutido no `PublicPage`,
**so that** as agregações da Story 4.3 (`page_views_7d`/`page_views_30d`) e o dashboard de analytics da Story 4.4 tenham dados brutos de impressões para consumir — completando, junto com 4.1, o ciclo bruto de telemetria do MVP (FR10, FR11) sem comprometer LGPD (NFR12) e preservando a ISR `revalidate=60` da `/[username]` (Story 2.7 — perf gain registrado no Lighthouse CI da 3.5).

### DDL canônico de `page_views` (verbatim — `schema-design.md §4 #page_views` linhas 605-619)

```sql
CREATE TABLE IF NOT EXISTS page_views (
  id              bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  page_id         uuid NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
  viewed_at       timestamptz NOT NULL DEFAULT now(),
  user_agent_hash bytea,
  ip_hash         bytea,
  CONSTRAINT chk_page_views_hash_size
    CHECK (
      (user_agent_hash IS NULL OR octet_length(user_agent_hash) = 32) AND
      (ip_hash         IS NULL OR octet_length(ip_hash)         = 32)
    )
);

COMMENT ON TABLE page_views IS 'Log append-only de page-views (FR10). Retenção 90d via pg_cron (NFR12).';
```

Índice (`schema-design.md §6` linhas 789-790):

```sql
CREATE INDEX IF NOT EXISTS idx_page_views_page_id_viewed_at
  ON page_views (page_id, viewed_at DESC);
```

- `page_id ... REFERENCES pages(id) ON DELETE CASCADE` → views somem quando page some (cascade chain: `pages.profile_id → profiles.id → auth.users.id`).
- **`id bigint identity`** — coerente com `click_events.id` (4.1). Append-only com volume potencial >1M/ano justifica bigint (2× menor em índice; sequence cache-friendly em B-tree).
- **Sem `updated_at`, sem trigger `set_updated_at`** — tabela append-only (`schema-design.md §4` análogo a `click_events`).
- `chk_page_views_hash_size` defende contra hash truncado/incorreto (32 bytes = output canônico sha-256). Espelhado 100% do `chk_click_events_hash_size` da 0007.

import { z } from 'zod';
import { hashPIINullable } from '@/lib/hash';
import { checkRateLimit } from '@/lib/rate-limit';
import { createAdmin } from '@/lib/supabase/admin';
import { insertPageView } from '@/lib/track';

// Runtime config (idem 4.1)
export const runtime = 'nodejs';
export const dynamic = 'force-dynamic';

// Body schema
const Schema = z.object({ page_id: z.string().uuid() });
const RATE_LIMIT = { max: 60, windowMs: 60_000 } as const;

export async function POST(request: Request): Promise<Response> {
  // 1. Parse + validate body
  const json = await request.json().catch(() => null);
  const parsed = Schema.safeParse(json);
  if (!parsed.success) return new Response(null, { status: 400 });
  const { page_id } = parsed.data;

  // 2. Extract IP + UA (REUSE 100% pattern da 4.1)
  const forwarded = request.headers.get('x-forwarded-for');
  const ip = forwarded?.split(',')[0]?.trim() || request.headers.get('x-real-ip') || null;
  const userAgent = request.headers.get('user-agent');

  // 3. Hash PII ANTES do rate-limit
  const ipHash = await hashPIINullable(ip);

  // 4. Rate limit (REUSE da 4.1)
  if (ipHash) {
    const key = ipHash.toString('hex');
    const { allowed, resetAt } = checkRateLimit(key, RATE_LIMIT);
    if (!allowed) {
      return new Response(null, {
        status: 429,
        headers: { 'Retry-After': String(Math.max(0, Math.ceil((resetAt - Date.now()) / 1000))) },
      });
    }
  }

  // 5. Resolve page + check published (DEV-6)
  const admin = createAdmin();
  const { data: page, error: selectError } = await admin
    .from('pages')
    .select('id, is_published')
    .eq('id', page_id)
    .maybeSingle();
  if (selectError) {
    console.error('[track/view] page lookup failed', selectError);
    return new Response(null, { status: 500 });
  }
  if (!page || !page.is_published) return new Response(null, { status: 404 });

  // 6. Insert via lib/track (handles dedup AC3) — DEV-7 → 204 uniforme
  const result = await insertPageView({ pageId: page_id, ip, userAgent });
  if (result.reason === 'error') return new Response(null, { status: 500 });
  return new Response(null, { status: 204 }); // inserted: true OR reason: 'duplicate'
}

### `lib/track.ts` — contrato (Task 4)

```typescript
/**
 * Server-side page view tracker.
 *
 * Hasheia PII (ip, user-agent) com HASH_SALT (REUSE lib/hash.ts da 4.1),
 * aplica dedup window de 30 min (AC3 — query app-side por
 * page_id + ip_hash + viewed_at >= now() - 30min), e insere row em
 * page_views via service-role (DEV-5 da 4.1 — admin bypassa RLS).
 *
 * RACE WINDOW (DEV-2): dois requests paralelos do mesmo ip_hash+page_id
 * podem ambos passar o SELECT antes do INSERT — duplicação <0.1% esperada,
 * aceitável para tracking estatístico (não-financeiro). Phase 2 pode adicionar
 * trigger-based dedup se análise mostrar abuse pattern.
 */
import { hashPIINullable } from '@/lib/hash';
import { createAdmin } from '@/lib/supabase/admin';

const DEDUP_WINDOW_MS = 30 * 60 * 1000; // 30 minutes per PRD AC3

type InsertResult = { inserted: true } | { inserted: false; reason: 'duplicate' | 'error' };

export async function insertPageView(input: {
  pageId: string;
  ip: string | null;
  userAgent: string | null;
}): Promise<InsertResult> {
  const ipHash = await hashPIINullable(input.ip);
  const uaHash = await hashPIINullable(input.userAgent);

  const admin = createAdmin();

  // Dedup window check (DEV-2). Bypass se ipHash ausente (nenhuma chave estável).
  if (ipHash) {
    const ipHashHex = '\\x' + ipHash.toString('hex');
    const cutoffIso = new Date(Date.now() - DEDUP_WINDOW_MS).toISOString();

    const { data: existing, error: dedupErr } = await admin
      .from('page_views')
      .select('id')
      .eq('page_id', input.pageId)
      .eq('ip_hash', ipHashHex)
      .gte('viewed_at', cutoffIso)
      .limit(1)
      .maybeSingle();

    if (dedupErr) {
      console.error('[track/view] dedup query failed', dedupErr);
      return { inserted: false, reason: 'error' };
    }
    if (existing) return { inserted: false, reason: 'duplicate' };
  }

  // Insert (DEV-4: bytea como \x<hex>, não base64).
  const { error: insertErr } = await admin.from('page_views').insert({
    page_id: input.pageId,
    user_agent_hash: uaHash ? '\\x' + uaHash.toString('hex') : null,
    ip_hash: ipHash ? '\\x' + ipHash.toString('hex') : null,
  });

  if (insertErr) {
    console.error('[track/view] insert failed', insertErr);
    return { inserted: false, reason: 'error' };
  }

  return { inserted: true };
}
```

- Função única, server-side only. Não exporta para client (zero chance de leak de service-role).
- REUSE `hashPIINullable` da 4.1 — não recriar Web Crypto wrapper.
- `DEDUP_WINDOW_MS` constante exportável se 4.3/4.4 precisarem mostrar o window na UI (não-prioritário).
