## Story

**As a** desenvolvedor,
**I want** uma tabela `click_events` (append-only, PII hashada) e um endpoint `POST /api/track/click` que registre cada clique em link (com resolução de link via service-role, rate-limit por `ip_hash` e hash sha-256 + salt para `ip`/`user-agent`),
**so that** as agregações da Story 4.3 e o dashboard de analytics da Story 4.4 tenham dados brutos para consumir — fechando o ciclo de valor do MVP (FR9, FR11) sem comprometer LGPD (NFR12) nem deixar a página pública dependente de JS para navegar (AC6, `architecture.md §Workflow 2` L714-740).

## Acceptance Criteria

> Copiados **verbatim** de `docs/prd.md` §Epic 4 > Story 4.1 (linhas 546-560). O estado pré-existente e as nuances de cada AC estão detalhados em **Dev Notes** — leia-os antes de implementar. Decisões de implementação e deviations PRD↔arch estão isoladas em **Dev Notes §Decisões & Deviations** com default fundamentado e fonte citada (NÃO inventar — Constitution Art. IV).

1. Migration cria `click_events` (id, link_id FK, clicked_at default now(), user_agent_hash, ip_hash).
2. Endpoint `POST /api/track/click` aceita `{ link_id }`; resolve link via service-role; rejeita se link inexistente ou page não publicada.
3. user_agent e ip são hashados (sha-256 + salt em env var) antes do insert.
4. RLS: insert allowed via service role only; select_own permite ao dono ler seus events.
5. Rate limiting básico: máx 60 events/min por ip_hash via lógica simples em-memory ou Redis-free fallback.
6. Página pública chama o endpoint via fetch beforeunload em cada link clicado (não bloqueia navegação).

CREATE TABLE IF NOT EXISTS click_events (

### Route Handler `app/api/track/click/route.ts` — contrato canônico

```typescript
// Imports
import { z } from 'zod';
import { hashPIINullable } from '@/lib/hash';
import { checkRateLimit } from '@/lib/rate-limit';
import { createAdmin } from '@/lib/supabase/admin';

// Runtime config
export const runtime = 'nodejs'; // Web Crypto + Buffer; força Node sobre Edge
export const dynamic = 'force-dynamic'; // sem cache p/ POST

// Body schema
const Schema = z.object({ link_id: z.string().uuid() });

export async function POST(request: Request) {
  // 1. Parse + validate body
  const body = await request.json().catch(() => null);
  const parsed = Schema.safeParse(body);
  if (!parsed.success) return new Response(null, { status: 400 });
  const { link_id } = parsed.data;

  // 2. Extract IP + UA from headers (Vercel proxy headers)
  const ip =
    request.headers.get('x-forwarded-for')?.split(',')[0]?.trim() ??
    request.headers.get('x-real-ip') ??
    null;
  const userAgent = request.headers.get('user-agent');

  // 3. Hash PII before any logging / rate-limit
  const ipHash = await hashPIINullable(ip);
  const uaHash = await hashPIINullable(userAgent);

  // 4. Rate limit (AC5): chave = ipHash hex; bypass se ipHash ausente
  if (ipHash) {
    const key = ipHash.toString('hex');
    const { allowed, resetAt } = checkRateLimit(key, { max: 60, windowMs: 60_000 });
    if (!allowed) {
      return new Response(null, {
        status: 429,
        headers: { 'Retry-After': String(Math.ceil((resetAt - Date.now()) / 1000)) },
      });
    }
  }

  // 5. Resolve link via service-role (AC2)
  const admin = createAdmin();
  const { data: link } = await admin
    .from('links')
    .select('id, page_id, pages!inner(is_published)')
    .eq('id', link_id)
    .maybeSingle();
  if (!link) return new Response(null, { status: 404 });
  // Type assertion needed: pages!inner is array-of-1 in Supabase typings
  const isPublished = (link.pages as unknown as { is_published: boolean }).is_published;
  if (!isPublished) return new Response(null, { status: 404 });

  // 6. Insert (service-role bypassa RLS)
  await admin.from('click_events').insert({
    link_id,
    user_agent_hash: uaHash ? uaHash.toString('base64') : null,
    ip_hash: ipHash ? ipHash.toString('base64') : null,
  });

  return new Response(null, { status: 204 });
}
```

> **Observação técnica:** a serialização final de `bytea` (base64 vs Buffer vs `\x` hex) é validada por Task 9.2 (smoke runtime) — ver DEV-4. Se Supabase JS aceitar Buffer direto, simplificar (omitir `.toString('base64')`); caso contrário, o exemplo acima é o caminho mais portável.

```typescript
import { env } from '@/lib/env';

const encoder = new TextEncoder();

export async function hashPII(value: string): Promise<Buffer> {
  const data = encoder.encode(value + env.HASH_SALT);
  const ab = await crypto.subtle.digest('SHA-256', data);
  return Buffer.from(ab);
}

export async function hashPIINullable(value: string | null | undefined): Promise<Buffer | null> {
  if (!value) return null;
  return hashPII(value);
}
```

### `lib/rate-limit.ts` — contrato (Task 5)

```typescript
/**
 * In-memory fixed-window rate limiter.
 *
 * LIMITAÇÃO FUNDAMENTAL (DEV-5): em serverless (Vercel Functions), cada cold
 * start cria nova instância → Map é per-instance. Múltiplas instâncias paralelas
 * podem aceitar tráfego acima do limite agregado. AC5 do PRD permite explicitamente
 * "em-memory ou Redis-free fallback" — isto é o fallback explícito.
 */
type Entry = { count: number; windowStart: number };
const store = new Map<string, Entry>();
let callCount = 0;

export function checkRateLimit(
  key: string,
  opts: { max: number; windowMs: number },
): { allowed: boolean; resetAt: number; remaining: number } {
  const now = Date.now();
  let entry = store.get(key);

  if (!entry || entry.windowStart + opts.windowMs < now) {
    entry = { count: 0, windowStart: now };
    store.set(key, entry);
  }

  // Cleanup piggybacked
  if (++callCount % 100 === 0) {
    for (const [k, v] of store) {
      if (v.windowStart + opts.windowMs * 2 < now) store.delete(k);
    }
  }

  if (entry.count >= opts.max) {
    return {
      allowed: false,
      resetAt: entry.windowStart + opts.windowMs,
      remaining: 0,
    };
  }

  entry.count++;
  return {
    allowed: true,
    resetAt: entry.windowStart + opts.windowMs,
    remaining: opts.max - entry.count,
  };
}

// Test-only escape hatch: limpar o store entre testes
export function __resetRateLimit(): void {
  store.clear();
  callCount = 0;
}
```

- Fixed-window é suficiente para "60/min/ip_hash" (AC5). Sliding window seria mais justo mas adiciona complexidade injustificada para MVP.
- `__resetRateLimit` exposto p/ Task 6.8 cenário (e) isolar runs (Vitest `beforeEach`).
