### §Drift — Discrepância Arquitetura ↔ Implementação (CRÍTICO para AC5)

Há um drift **documentado e consciente** entre os exemplos canônicos do `architecture.md` e a implementação real:

- **Arquitetura (canonical examples):** `docs/architecture.md` §Frontend Architecture linha 1075, §Frontend Error Handling linha 2558 usam `import { useToast } from '@/components/ui/use-toast'` com API `toast({ title, description, variant: 'destructive' })` — pattern do **Radix shadcn Toast**.
- **Implementação real (Stories 1.5/1.6):** o projeto adotou **`sonner`** — `import { toast } from 'sonner'`, API `toast.success(msg)` / `toast.error(msg)`. Justificativa registrada em **Story 1.5 Dev Notes**: _"`sonner` — toast notifications (shadcn/ui-recommended; substitui Radix Toast deprecado)"_. `components/ui/sonner.tsx` é o wrapper `<Toaster/>` (não existe `components/ui/use-toast.ts`).
- **Consumidores atuais (7):** `components/auth/{LoginForm,ResetPasswordRequestForm,LogoutButton,SignupForm,ResetPasswordConfirmForm}.tsx`, `components/dashboard/ResendEmailButton.tsx` — todos `import { toast } from 'sonner'` direto.

**Decisão (default proposto, fundamentado — NÃO inventar alternativa):** manter **`sonner`** como base (decisão da Story 1.5 supera os exemplos canônicos mais antigos do arch; `sonner` é o recomendado oficial do shadcn pós-deprecação do Radix Toast; 7 consumidores já o usam; arch §Tech Stack lista shadcn/ui Radix primitives mas não fixa `use-toast`). O `lib/toast.ts` (AC5) é o **ponto de reconciliação**: encapsula `sonner` atrás de uma API estável do projeto, removendo o acoplamento direto. Se o PO exigir compat com a assinatura `{ title, description, variant }` dos exemplos do arch, o helper pode expor adicionalmente `notify({ title, description, variant })` mapeando `variant:'destructive'`→`error`. **Registrar no Change Log que o arch precisa de erratum** (handoff não-bloqueante: atualizar `architecture.md` §1075/§2558 para refletir `sonner`/`lib/toast` numa story de docs futura — não fazer nesta story, escopo é seed do DS).
