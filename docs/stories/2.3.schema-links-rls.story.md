## Story

**As a** desenvolvedor,
**I want** uma tabela `links` pertencente a `pages` com RLS composta (JOIN ao owner via `pages`), constraint de ordenação `(page_id, position)` UNIQUE DEFERRABLE e cenários RLS testados em CI,
**so that** operações futuras de CRUD (Story 2.5) e reorder drag-and-drop (Story 2.6) sejam seguras, consistentes e atômicas, e a página pública possa renderizar links visíveis ordenados (FR6, FR7, FR8).

## Acceptance Criteria

> Copiados **verbatim** de `docs/prd.md` §Epic 2 > Story 2.3 (linhas 398-402). O estado pré-existente e as nuances de cada AC estão detalhados em **Dev Notes** — leia-os antes de implementar. Decisões de implementação e deviations PRD↔arch estão isoladas em **Dev Notes §Decisões & Deviations** com default fundamentado e fonte citada (NÃO inventar — Constitution Art. IV).

1. Migration cria `links` (id, page_id FK, title, url, icon, is_visible, position, created_at, updated_at).
2. Constraint: position UNIQUE per page_id.
3. RLS: select_own + insert_own + update_own + delete_own + select_public (joined com pages.is_published=true e links.is_visible=true).
4. Trigger ou Server Action garante position contígua (sem buracos) após delete.
5. Testes RLS cobrem todas as combinações + caso de tentar inserir link em página de outro usuário (deve falhar).

### DDL canônico de `links` (verbatim — `schema-design.md §4 #links` linhas 522-541)

```sql
CREATE TABLE links (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  page_id     uuid NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
  title       text NOT NULL CHECK (length(title) BETWEEN 1 AND 100),
  url         text NOT NULL CHECK (url ~* '^https?://'),
  icon        text CHECK (icon IS NULL OR icon ~ '^[a-z0-9-]{1,40}$'),
  is_visible  boolean NOT NULL DEFAULT true,
  position    integer NOT NULL CHECK (position >= 0),
  created_at  timestamptz NOT NULL DEFAULT now(),
  updated_at  timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT uniq_links_page_position
    UNIQUE (page_id, position) DEFERRABLE INITIALLY DEFERRED
);

CREATE TRIGGER trg_links_set_updated_at
  BEFORE UPDATE ON links
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();

COMMENT ON TABLE links IS 'Items clicáveis na página pública (FR6, FR7, FR8).';
COMMENT ON COLUMN links.position IS 'Ordem de exibição (UNIQUE per page, DEFERRABLE para reorder atômico).';
```

Índices (`schema-design.md §6` linhas 750 + 757-768 — Q4 RESOLVED):

```sql
CREATE INDEX idx_links_page_id ON links (page_id);                          -- FK index, AP-2
CREATE INDEX idx_links_page_id_position_visible
  ON links (page_id, position) WHERE is_visible = true;                     -- parcial, AP-1 (Q4)
```

- `page_id ... REFERENCES pages(id) ON DELETE CASCADE` → links somem quando a page some (que some quando profile/auth.users some — cascade chain, `schema-design.md §2` linha 209).
- `uniq_links_page_position` cobre **AC2** (position UNIQUE per page_id); `DEFERRABLE INITIALLY DEFERRED` é o primitivo do reorder atômico (AC4 — Story 2.6). O índice automático da UNIQUE **não serve queries** (`schema-design.md §6` linha 745) → os 2 índices acima são necessários.
- `id` usa `gen_random_uuid()` (não-sequencial; segurança em URLs futuras `/api/links/{id}`, `schema-design.md §7` padrão de `pages.id`).

### Estratégia RLS de `links` (AC3) — SQL canônico `architecture.md §RLS` linhas 965-985

| Operação         | Policy                | Predicado                                                                                                | Fonte                    |
| ---------------- | --------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------ |
| SELECT (owner)   | `links_select_own`    | `EXISTS (SELECT 1 FROM pages p WHERE p.id = page_id AND p.profile_id = auth.uid())`                      | arch.md L966-976 (split) |
| SELECT (público) | `links_select_public` | `is_visible = true AND EXISTS (SELECT 1 FROM pages p WHERE p.id = page_id AND p.is_published = true)`    | arch.md L966-976 (split) |
| INSERT           | `links_insert_own`    | `WITH CHECK (EXISTS (SELECT 1 FROM pages p WHERE p.id = page_id AND p.profile_id = auth.uid()))`         | arch.md L977-979         |
| UPDATE           | `links_update_own`    | `USING + WITH CHECK (EXISTS (SELECT 1 FROM pages p WHERE p.id = page_id AND p.profile_id = auth.uid()))` | arch.md L980-982         |
| DELETE           | `links_delete_own`    | `USING (EXISTS (SELECT 1 FROM pages p WHERE p.id = page_id AND p.profile_id = auth.uid()))`              | arch.md L983-985         |

- **DEV-2:** arch.md tem **1** policy SELECT combinada (`links_select_public`); aqui são **2** (`links_select_own` + `links_select_public`) p/ casar o naming verbatim do AC3 — Postgres OR-combina permissivas → funcionalmente idêntico (mesma decisão de 2.2 DEV-2, APPROVED).
- `WITH CHECK` no `links_update_own` adicionado por simetria anti-reassign (impede mover um link p/ page de outro user via UPDATE de `page_id`) — espelha o hardening de `pages_update_own` (0003:106-110), padrão validado 2.2.
- A subquery `EXISTS (… JOIN/SELECT pages …)` é reavaliada por linha em scans amplos → o índice `pages.profile_id` (UNIQUE auto de 0003) e `idx_links_page_id` mitigam (`schema-design.md §9` linha 1010). `auth.uid()` é STABLE no Supabase (cacheável por linha).
- Naming `{tabela}_{op}_{escopo}` espelha 0002/0003. `DROP POLICY IF EXISTS` antes de cada `CREATE POLICY` (idempotência, padrão 0003:92-110).
- **Sem policy contra DELETE/UPDATE de `click_events`/`page_views`** — fora de escopo (tabelas de Stories 4.x; `links` só referencia `pages`).

### AC4 — contiguidade de `position` (resumo `schema-design.md §7 Q1 RESOLVED` linhas 899-925)

**Decisão arquitetural fechada (Q1 RESOLVED):** `UNIQUE (page_id, position) DEFERRABLE INITIALLY DEFERRED` + **leave gaps on delete (NÃO compactar)**. Reorder atômico funciona assim (Story 2.6, fora de escopo de 2.3):

```sql
BEGIN;
  UPDATE links SET position = 0 WHERE id = 'id3' AND page_id = 'X';
  UPDATE links SET position = 1 WHERE id = 'id1' AND page_id = 'X';
  UPDATE links SET position = 2 WHERE id = 'id2' AND page_id = 'X';
COMMIT;  -- uniqueness check (DEFERRED) avaliado só aqui → swap sem coluna temp
```

- Trigger shift-on-delete **rejeitado** por arch (lock contention; compactar não traz benefício — client ordena por `position ASC` e ignora gaps; gaps normalizam em reorder manual). Fractional indexing também rejeitado.
- **Entregável de schema desta story p/ AC4:** a constraint `DEFERRABLE` (primitivo) + comentário explícito no SQL (Task 1.10). A lógica "garante contígua após delete" é a Server Action `reorderLinks()` da **Story 2.6** — ver DEV-4.
